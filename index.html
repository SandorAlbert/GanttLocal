Help

Getting started

GanttLocal is a project scheduler that runs on your machine. There is no account and no cloud.

  1. Type a task name in the table, press Tab and give it a number of days.
  2. Press Ins for the next task. Repeat until the work is listed.
  3. Select two tasks that must happen one after the other and press Ctrl+L. The second one now starts when the first one finishes, and it moves along whenever the first one slips.

Everything is saved automatically into a plain file on your own disk. There is no account and no cloud.

The three ideas worth knowing

  • Duration, not dates. You give a task a length in working days; dates come out of the plan. That is what makes the chart move by itself when something changes.
  • Dependencies. "This can only start once that is done." See Depends on.
  • Summaries. Indent tasks under a heading and the heading reports their span and progress. See Tasks and outline.

Reading the chart

Colour is used for exactly one thing: whether a task is as far along as it should be by today. The yardstick is time already spent, so being at 20% is fine on day one of a task and alarming on its last day.

A task counts as behind when it is more than 10 percentage points short of the working time it has already consumed. At risk means it is short by less than that. Anything you mark 100% done stays "done", even if it finished late.

Shapes

  • Bar - a normal task. The solid part is the share you marked done.
  • Diamond - a milestone, a task of zero days. Use it for a decision, a delivery or a deadline.
  • Slim bracket - a summary task. It spans its children and cannot be dragged.
  • Thin arrow - a dependency, drawn from the driving task to the one that follows.
  • Vertical line with a cap in the header - today.
  • Light grey columns - non-working days, taken from the calendar in Settings.

Tasks and outline

A project is one flat list of rows. Indentation, not a separate structure, creates the hierarchy: indent a row and the row above becomes its summary.

  • A summary has no dates of its own. Its bar starts with the earliest child and ends with the latest, and its progress is the average of its children weighted by their length.
  • Its Days, Start and % cells cannot be edited, because they are results.
  • Click the small - or + in front of a summary, or press Space, to fold it. Folded children still count in every calculation.
  • A milestone is a task of 0 days, shown as a diamond. Set it with the Milestone button or by typing 0 into Days.
  • Manual (in the details panel) pins a task to the date you typed and stops predecessors from pushing it. Use it sparingly, it switches the automation off for that row.

WBS

The WBS column is the outline number, so 2.3 is the third child of the second top-level task. It renumbers itself as you move rows around. The id in the details panel is the permanent number used by dependencies and never changes.

Depends on (predecessors)

A dependency says "this task cannot happen until that one has". The task that comes first is called the predecessor; the one waiting is the successor. This is the same idea, and the same wording, as Microsoft Project's Predecessors column.

The Depends on cell lists the ids the task waits for: 7 means "wait for task 7". Several are separated by commas: 7, 12. Make one by selecting two rows and pressing Ctrl+L, by dragging the dot that appears after a bar onto another bar, or by typing ids into the cell.

The point of a dependency is that it keeps holding. Push the predecessor out by three days and everything behind it follows, which is why a plan built from dependencies stays true and a plan built from typed dates does not.

The four types

Written after the id, for example 7SS. Plain 7 means finish to start, which is what you want almost always.

FS - finish to start B starts after A finishes. The default.
SS - start to start B may start once A starts. For work that runs alongside.
FF - finish to finish B cannot finish before A does. For work that must end together.
SF - start to finish B must be finished by the time A starts. Rare, used for handovers.

Delay and overlap (lag)

Add days after the type to wait longer, or negative days to overlap: 7FS+2d starts two working days after task 7 ends, 7SS-1d starts one day before task 7 starts. Lag is counted in working days.

Circular chains are refused: if A waits for B, B cannot be made to wait for A. Should one ever reach the file, the rows involved are shown in red text and named in the status bar.

Dates and calendar

Dates are shown as 19.08.2026. When typing you may also use 19.8.26, 19.8. for the current year, or 2026-08-19. Settings > Date format switches the display to ISO.

Only working days count. A five-day task starting on a Thursday finishes on the following Wednesday. Which weekdays count, and which single days are holidays, is set per project under Settings > Working days. Change either one and the whole plan re-flows.

Editing Finish keeps the start and changes the length. Dragging the middle of a bar moves the task; dragging an edge changes its length.

Constraints

By default a task runs as early as its predecessors allow. A constraint overrides that for one row.

As soon as possibleThe normal behaviour: follow the predecessors.
Start no earlier thanNever begins before the date, but may begin later if a predecessor is late. This is what you get when you drag a task without predecessors to a later date.
Finish no later thanA deadline. The task is not moved by it, but you are warned in the status bar when it finishes after the date.
Must start onNails the task to one date, whatever the predecessors say. If they cannot deliver in time you are warned.

Critical path and slack

Slack is how many working days a task can slip before it pushes the project's end date. The Slack column shows it per task.

The critical path is the chain of tasks with no slack at all: the sequence that decides when the project finishes. Delay any of them by a day and the whole project ends a day later; speed up something off the path and nothing changes. Those rows carry a small marker before the name and a dark outline around the bar, so that colour stays free for progress. Turn the marking off under Settings.

Chat

Chat opens a dock for the current project. You can ask questions about the plan and request changes. Replies stream token by token as the local model generates them. The assistant proposes structured edits; you Apply or Reject them. Apply is one undo step (Ctrl+Z reverses the whole batch) and then auto-saves.

Each project keeps its own chat history under data/.assistant/.

Chat is optional. Install with python tools/install_assistant.py (CPU) or python tools/install_assistant.py vulkan (GPU via Vulkan), place llm/models/chat.gguf, and see llm/README.md. Turn on Settings > Assistant > Use GPU after the Vulkan install. Without those, the rest of GanttLocal still works.

Where data lives

Each project is one readable JSON file in the data folder next to the program, for example data/Project.json. Edits are written a moment after you stop typing; previous versions are kept in data/.backups/ (last 10 per project).

Copy, mail or version those files as you like. Settings > Export JSON writes a copy to your downloads, Import JSON takes one in as a new project. Export HTML writes a single view-only page of the table and chart: no toolbar, no server, no install, just open it. If a file is changed by something else while it is open here, the status bar says file changed: click that label to reload from disk, or Ctrl+S to overwrite with this version.
